# 社工密码字典生成工具 PassSmith

## 一、项目概述

一个基于 Python 的社会工程学密码字典生成工具，具备可视化图形界面（GUI）。用户输入目标的个人信息（姓名、手机号、身份证号、工号、学号、邮箱等），工具根据内置规则和用户自定义规则，智能生成高命中率的密码字典文件。

**核心价值**：相比通用暴力字典，基于目标个人信息的社工字典命中率提升3-5倍，极大提升渗透测试效率。

**技术栈**：
- 语言：Python 3.9+
- GUI框架：PyQt5（成熟稳定，跨平台，组件丰富）
- 核心依赖：pypinyin（中文拼音转换）、itertools（组合排列）、tqdm（进度显示）

提供"快捷模式"和"高级模式"两种配置入口。

#### 快捷模式（默认）

- [x] 身份证后4/6/8位（默认开启）

- [x] 大小写组合 zs/Zs/ZS/zS、Zhang.san/Zhang.San（默认开启，可关闭压缩字典）
- [ ] 姓名首字母+数字组合
- [ ] 邮箱前缀衍生
- [ ] 工号/学号衍生
- [ ] Leet Speak替换（如 a→@, e→3, o→0）
- [ ] 常见键盘模式（qwerty, 1qaz@wsx, 1q2w3e4r）

#### 高级模式
点击"高级配置"按钮展开，提供精细控制：

**1. 站点密码策略（预设一键套用）**

不同目标系统的密码策略差异很大，手动调 5 个控件太慢：

| 预设 | 长度 | 复杂度要求 | 字符集 | 适用场景 |
|------|------|-----------|--------|---------|
| 宽松 | 6-20 | 无 | 任意 | 内网弱策略、靶场、CTF |
| 标准 | 8-20 | 数字 + 字母 + 特殊字符 + **大小写混合** | 任意 | 等保三级、AD 域、OA |
| 字母数字 | 6-16 | 数字 + 字母 | **仅字母数字** | 老系统、工控、部分银行 |
| 数字 PIN | 4-8 | 数字 | **仅数字** | 手机锁屏、支付密码、门禁 |

- 预设只做一次性套用，套用后仍可手动微调任意参数
- 「大小写混合」与「大小写组合」联动：勾选混合会自动开启大小写变体（否则没有大写形态可用），反之关闭变体会自动取消混合要求
- **策略感知生成**：要求大小写混合时，纯小写/纯大写形态在生成阶段就被剔除，组合预算让给有效形态（同配置下有效条目 +34%）

**2. 密码长度限制**
- 最小长度：[5] （默认5：`zs123`、`abc123` 这类 5 位密码在旧系统/内网仍常见）
- 最大长度：[20]（默认20）

**3. 复杂度筛选**
- 必须包含数字 / 字母 / 特殊字符 / **大小写混合**
- 字符集：[任意字符] / [仅字母数字] / [仅数字]
- 5 万条以内时预估值是**精确生成计数**（含筛选与去重，误差 0，耗时 3-6ms）；
  超过 5 万条才退回算术估算并标注「估算」

**4. 自定义弱口令列表**
- 文本框，每行一个，预设弱口令（**按真实泄露库频率排序**，前列优先进入组合与字典前段）：
```
123456, 12345678, 123456789, 520, 1314, 111111, 000000,
1234567, 12345, 1234, 123, 666, 888, 999, 000,
password, qwerty, abc123, admin, root, test, iloveyou,
welcome, master, a123456, qq123456, woaini1314, 147258, 1qaz2wsx
```
- 支持用户添加/删除/导入
- **分隔符兼容中英文标点**：英文逗号 `,`、中文逗号 `，`、顿号 `、`、分号 `;；`、换行都可以。
  中文输入法下打出的全角逗号不会再导致整行被当成一条弱口令
- 「自定义分隔符」输入框额外允许**空格分隔**（分隔符都是单字符符号）；
  弱口令列表刻意不按空格切分——密码本身可能含空格，拆开会污染内容
- **弱口令本身会作为独立密码输出**（0 级通道，排在字典最前）——`123456`、`password` 这类通用密码命中率最高且不依赖个人信息
- **不填任何个人信息也能生成**：只输出纯弱口令字典（点生成时会确认一次）。
  适合只需要一份通用弱口令表、或想先验证某个词是否生效的场景
- 注意：弱口令自身同样要过「长度 / 复杂度 / 字符集」筛选。把 `123` 加进列表但
  最小长度设 8，它不会出现在结果里——这是筛选生效，不是规则失效

**5. 自定义前缀**
```
!, @, #, $, &, *, (, ), _, -, +, =
```

**6. 自定义后缀**
```
!, @, #, $, 1, 12, 123, !@#, 00, 01, 66, 88, 99
```

**7. 自定义分隔符**
```
., _, -, @, #, 无分隔
```

**8. 组合深度控制**
- 零级：纯弱口令（如 `123456`、`password`）——命中率最高，排字典最前
- 单元素衍生：1级（如 name → name123、name!、!name）
- 双元素组合：2级（如 name+birthday → name0901）
- 三元素组合：3级（如 name+weak+suffix → `Zs123!`、`zhangsan@2024`；name+birthday+weak → `name0901!`）
- 最大组合深度：[3]（默认3，建议不超过4，否则字典膨胀过快）
- **反向拼接降权**：`123zhangsan`（弱口令+姓名）真实频率远低于 `zhangsan123`，只保留 3 个最常用弱口令做前缀，避免占满字典前段

**三元素阶段的完整通道**（国内密码的主流形态）：
| 通道 | 示例 | 弱口令取材 |
|------|------|-----------|
| 姓名+弱口令+特殊字符 | `Zs123!` `zhangsan123456#` `zs520!` | 数字型弱口令优先（`zhangsanpassword!` 这类复合不成立） |
| 姓名+分隔符+弱口令 | `zs@123` `zs#123` `zhang.san_1234` | 头部常用项 + 尾部均匀抽样，保证自定义项能进组合 |
| 姓名+生日+弱口令/后缀 | `zhangsan1990!` `zs0115#` | 均匀抽样 |
| 姓名+手机号+弱口令 | `zhangsan5678` | 均匀抽样 |

**9. 自定义规则编辑器**
提供一个文本编辑区，用户可以编写自定义生成规则。**默认已内置一条**：

```
{姓名首字母}{弱口令}{分隔符}
```

生成 `zs123@`、`zs520#` 这类「缩写 + 弱口令 + 结尾特殊字符」形态（很多系统强制要求特殊字符结尾）。
不需要可以删掉，或改成自己的规则。语法如下：
```
{姓名}         → 替换为姓名全拼
{姓}           → 替换为姓的拼音
{名}           → 替换为名的拼音
{姓名首字母}   → 替换为姓名拼音首字母（如zs）
{生日全}       → 替换为19900101
{生日年}       → 替换为1990
{生日月日}     → 替换为0101
{生日短}       → 替换为900101
{手机号}       → 替换为完整手机号
{手机后4}      → 替换为手机后4位
{手机后6}      → 替换为手机后6位
{身份证后4}    → 替换为身份证后4位
{身份证后6}    → 替换为身份证后6位
{工号}         → 替换为工号
{学号}         → 替换为学号
{邮箱前缀}     → 替换为@前面的部分
{弱口令}       → 遍历弱口令列表
{前缀}         → 遍历前缀列表
{后缀}         → 遍历后缀列表
{分隔符}       → 遍历分隔符列表
```

示例规则：
```

{姓名首字母}{生日月日}
{姓}{分隔符}{手机后4}
{姓名}{后缀}
{前缀}{姓名首字母}{生日短}
{邮箱前缀}{弱口令}
```

### 2.3 字典生成引擎

#### 核心算法

**1. 中文姓名处理**
```python
import pypinyin
from core.case_handler import case_variants, join_case_variants

def get_name_variants(chinese_name, full_case=True):
    """从中文姓名生成所有变体（绝不返回原始汉字）"""
    syllables = [p for p in pypinyin.lazy_pinyin(chinese_name) if p.isascii()]
    surname, given = split_surname(chinese_name)   # 支持复姓：欧阳/司马/诸葛…

    variants = []
    # 1) 全拼 × 大小写 × 分隔符（''、'.'、'_'、'-'）
    variants += join_case_variants(syllables, ('', '.', '_', '-'), full_case)
    # 2) 首字母缩写：两字符全枚举 zs / Zs / ZS / zS
    variants += case_variants([p[0] for p in syllables], '', full_case)
    # 3) 姓全拼+名首字母：zhangs / Zhangs / ZHANGS
    # 4) 仅姓：zhang / Zhang / ZHANG
    # 5) 音节反向（名+姓）：sanzhang / Sanzhang / SANZHANG / SanZhang
    # 6) 姓首字母+名全拼：zsan / Zsan / ZSAN
    return ascii_variants(variants)  # 只保留可打印 ASCII
```

大小写展开原则（`core/case_handler.py`）：
- **按 token（音节/首字母）边界组合，绝不逐字符做 2^n 枚举**——`zhangsan` 逐字符有 256 种大小写，其中 250 种没人用
- 单词 token 只有 4 种真实形态：`zhangsan` / `Zhangsan` / `ZHANGSAN` / `ZhangSan`
- 两字符首字母缩写全枚举 4 种：`zs` / `Zs` / `ZS` / `zS`（写法都真实存在）
- CamelCase（`ZhangSan`）只在每个 token ≥2 字符时生成，避免 `ZhangS` 这类垃圾

姓名变体还包括：
- **叠字**：张三 → `sansan` / `Sansan`（中文昵称高频形态，昵称/宠物名同样适用）
- **多音字姓**：单/解/查/曾/仇/朴/区/乐/覃/缪/都/种/尉/阚/盖等姓的正确读音变体（`shantingting`），
  默认读音与姓氏读音同时输出；映射表已按 pypinyin 无声调默认读音逐字复核
- **组合代表名单** `get_name_combination_variants`：2/3 级组合从完整变体列表头部取材只会拿到全拼形态，
  组合阶段改用按形态组抽出的代表名单（全拼/分隔符/缩写/姓全拼/反向约 10 个），保证 `zs1995`、`zhangs!@#`、`sanzhang2024` 都能生成

**2. 生日处理**
```python
def get_birthday_variants(birthday_str):
    """从生日字符串生成各种格式变体"""
    # 输入格式：1990-01-15
    year, month, day = birthday_str.split('-')
    variants = [
        birthday_str.replace('-', ''),  # 19900115
        year,                            # 1990
        year[2:],                        # 90
        month + day,                     # 0115
        day + month,                     # 1501
        year[2:] + month + day,          # 900115
        day + month + year[2:],          # 150190
        month + day + year[2:],          # 011590
        year + month,                    # 199001
        # 注意：不放「年+日」（199015）——1990 年 15 月是不存在的日期
    ]
    # 去除前导零的变体
    for v in list(variants):
        if v.startswith('0'):
            variants.append(v.lstrip('0') or '0')
    return list(set(variants))
```

输入先做合法性校验（`_valid_date`：年份 1900-2100、月份 1-12、日期按月份与闰年判定）。
`1990-13-45` 这类非法日期直接返回空，不产出 `19901345`、`199015` 之类永远不可能命中的垃圾组合。

**日期写法容错**（批量 CSV / 模板 / 粘贴场景）：
`1988-03-12`、`1988/03/12`、`1988.03.12`、`1988年3月12日`、`19880312`、`88-03-12`
全部归一到同一套变体；两位年份自动补世纪（`05` → 2005、`95` → 1995）。
无法识别的输入返回空，**不会把原串当密码素材**。

```python
def get_phone_variants(phone):
    """从手机号生成变体"""
    if not phone or len(phone) < 4:
        return []
    variants = [
        phone,              # 完整11位
        phone[3:],          # 后8位
        phone[5:],          # 后6位
        phone[7:],          # 后4位

        phone[:3] + phone[7:],  # 号段+后4位
    ]
    return list(set(variants))
```

```python
def get_email_variants(email):
    """从邮箱生成变体"""
    if not email or '@' not in email:
        return []
    prefix, domain = email.split('@')
    variants = [
        prefix,                         # 邮箱前缀
        prefix.capitalize(),            # 首字母大写
        prefix.upper(),                 # 全大写
        prefix + '@' + domain,          # 完整邮箱
        prefix.replace('.', ''),        # 去点
        prefix.replace('.', '_'),       # 点换下划线
        prefix.replace('.', '-'),       # 点换短横线
    ]
    return list(set(variants))
```

**6. Leet Speak 替换**
```python
def leet_speak(word):
    """Leet Speak变体：a→@, e→3, i→1, o→0, s→$, t→7"""
    leet_map = {'a': '@', 'e': '3', 'i': '1', 'o': '0', 's': '$', 't': '7'}
    variants = [word]
    for i, char in enumerate(word.lower()):
        if char in leet_map:
            new_variants = []
            for v in variants:
                new_variants.append(v)
                new_variants.append(v[:i] + leet_map[char] + v[i+1:])
            variants = new_variants
    return list(set(variants))
```

```python
            results.add(v)

                results.add(v + weak)

            for suffix in suffixes:
                results.add(v + suffix)

    categories = list(elements.keys())

        for j in range(len(categories)):
            if i == j:
                continue
            for v1 in elements[categories[i]]:
                for v2 in elements[categories[j]]:
                    results.add(v1 + v2)
                    for sep in separators:
                        results.add(v1 + sep + v2)
                    for weak in weak_passwords:
                        results.add(v1 + v2 + weak)

    # 3级：三元素组合（可选）
    if max_depth >= 3:
        for i in range(len(categories)):
            for j in range(len(categories)):
                for k in range(len(categories)):
                    if i == j or j == k or i == k:
                        continue
                    for v1 in elements[categories[i]][:5]:  # 限制数量防膨胀

```

**8. 自定义规则解析器**
```python
def parse_custom_rule(rule_str, context):
    """
    解析自定义规则，如 {姓名}{生日年}
    context: 包含所有信息变体的字典
    返回：该规则生成的所有密码列表
    """
    import re
    tokens = re.findall(r'\{([^}]+)\}|([^{]+)', rule_str)
    parts = []
    for placeholder, literal in tokens:
        if placeholder:
            key = placeholder.strip()
            if key in context and context[key]:
                parts.append(context[key])
            else:
                parts.append([''])  # 占位，不阻断后续
        else:
            parts.append([literal])
    return [''.join(combo) for combo in product(*parts)]
```

### 2.4 输出控制模块

#### 界面区域
- **实时计数器**：显示当前已生成的密码数量，用醒目数字显示

#### 导出功能
- 导出为 .txt 文件（每行一个密码）
- 导出为 .csv 文件（单列「密码」；来源规则需生成时全程追踪，暂不支持）

    选 GBK 时按 GBK 写、不加 BOM

- 支持分片导出（当字典过大时，按指定行数拆分为多个文件）
- **分档导出**：勾选后一次产出 `_top100.txt` / `_top1000.txt` / 全量三个文件。
  在线爆破受账号锁定限制，实际打法是先试 Top100 → Top1000 → 全量，分档文件直接对应这三个阶段
- **复制全部**：一键把全部结果写入剪贴板（`Ctrl+Shift+C`），可直接粘到 Burp Intruder / 自定义脚本
- 导出快捷键 `Ctrl+S`

- **合并去重**：多选字典文件，逐行流式读取（不吃内存），跳过 `#` 注释行，保序去重，

  其余标记为「排除」。用于二次爆破——已试过/已锁定的密码从新字典中剔除，
  省账号锁定次数。完成提示「基准 N 条 - 排除 M 条 = 剩余 K 条」

#### 3. 配置模板
- 把当前信息输入 + 规则配置存成模板（`output/templates/*.json`）
- 加载即完整回填两个面板（含长度、策略筛选、字符集、自定义规则、弱口令列表）

#### 4. 生成历史
- 每次生成自动记录：时间、条数、目标摘要、规则摘要（长度区间/组合深度/复杂度要求）
- 保留最近 10 条，可清空

## 五、关键设计决策

### 4.1 性能优化
- **生成过程使用生成器（yield）**，避免一次性构建巨大列表导致内存溢出
- **多线程**：生成任务在后台线程执行，不阻塞 UI
- **实时去重**：使用 set 增量去重，而非生成完再统一去重
- **预估机制**：生成前先计算组合数，超阈值（默认50万条）弹窗警告

### 4.2 安全考量
- 界面启动时显示"仅供授权安全测试使用"声明
- 生成的字典文件头部添加注释说明用途
- 不内置任何真实个人信息样本

### 4.3 扩展性
- 规则处理模块采用插件式架构，新增信息类型只需添加对应 handler
- 自定义规则语法可扩展，支持未来添加更多占位符
- 配置文件独立于代码，用户可自定义弱口令/前后缀列表
- **配置文件注释规则**：只有 `# `（# 后跟空白）开头才算注释行。`#` 本身是合法的后缀/分隔符，
  早期按「# 开头」判注释会把这一类整行吞掉

### 4.4 密码字符集硬约束（ASCII-only）

字典中每一条密码必须只由**可打印 ASCII（0x20~0x7E）**组成，且首尾无空白。汉字、全角字符、emoji、制表符/换行一律不得出现：

- 中文信息（姓名/昵称/宠物/父母/伴侣/公司/城市）只输出**拼音变体**，绝不输出原文
- 复姓（欧阳/司马/诸葛…）按复姓切分，避免把「欧/阳」误拆成 `ouynn` 这类永远不会命中的垃圾变体
- 输入先做归一化（NFKC 全角转半角 + 去零宽字符），避免 `１３８` 这类全角输入绕过校验
- 四道闸门层层拦截：变体生成器 → `_build_elements` 元素清洗 → `emit()` 出口校验 → `filter_passwords` 管道首道字符集过滤
- 通配路径（自定义规则字面量、工号/微信号/常用ID 等自由文本字段）由出口闸门兜底

违规示例：`张三123`、`password张三`、`zhangsan的生日` —— 这类条目在任何真实登录系统上都无效，只会污染字典、拉低命中率。

### 4.5 大小写组合策略

「大小写组合」规则（默认开启，可勾选关闭）控制姓名/昵称/宠物等文本变体的大小写展开：

| 形态 | 示例（张三） | 说明 |
|------|-------------|------|
| 全小写 | `zhangsan` / `zhang.san` | 主形态 |
| 首 token 大写 | `Zhangsan` / `Zhang.san` | 次常见 |
| 全大写 | `ZHANGSAN` / `ZHANG.SAN` | 老系统常见 |
| CamelCase | `ZhangSan` / `Zhang.San` | 仅各 token ≥2 字符 |
| 缩写全枚举 | `zs` / `Zs` / `ZS` / `zS` | 仅两字符缩写，四种写法都真实存在 |

关闭该规则时每组只保留全小写形态，字典体积约减半，适合目标系统不区分大小写或需要控制字典规模的场景。

### 4.6 输入校验与预估校准

**输入校验**（`ui/info_input_panel.py`）：手机号（11 位，容忍 +86/分隔符）、身份证（15 位数字或 17+校验位）、QQ（5-11 位数字）、邮箱（前缀@域名）实时校验，不合法时输入框红框 + tooltip 提示。**只提示不阻断**——特殊系统的非标账号依然允许生成。

**预估校准**（`core/combiner.py`）：纯算术预估不含去重建模，实测 7 组画像的预估/实际比值在 1.08~1.25（字段越多交叉重叠越多）。统一乘校准因子 `ESTIMATE_CALIBRATION = 0.85` 后偏差收敛到 ±10% 以内，大字典保持轻微高估（警告线安全方向）。

### 4.7 界面设计规范

**配色**：深色为深海军蓝（`#0b1220` 系），浅色为冷灰白（`#eef1f7` 系）。
蓝色 `#4d8dff` 作强调（焦点 / 选中 / 读数），绿色 `#10b981` 作主操作按钮。

| 决策 | 原因 |
|------|------|
| 深色靠**表面亮度分层**（`bg → card → card_hover`），不用阴影 | QSS 不支持 box-shadow；深色下阴影也几乎不可见 |
| 字阶 11 / 12 / 13 / 15 / 18 | 13/12/11 这种密集小字阶会让层级糊成一片 |
| 圆角 4px（控件）/ 8px（卡片） | 大圆角削弱工具感 |
| 关键数字用等宽字体 + 蓝色 | 条数这类读数需要一眼可辨，等宽避免数字跳动 |
| 主按钮纯色，不用渐变 | 渐变按钮是最典型的模板化观感 |
| 分组标题 15px/700 + 字距 0.4px | 和 13px 正文拉开层级 |
| 核心分组 `emphasis="true"`（更亮表面 + 左侧 3px 蓝条） | 5 个分组同权重时用户找不到起点 |
| 输入框垂直内边距 6px、卡片内边距 16px | 更小会让文字贴边框，长时间录入很累 |

**布局**：
- 「社交关系」默认折叠（点底部标题展开，展开时自动滚到可见）——6 个选填字段平铺会把
  整列撑到需要滚动，导出区被挤出视口导致按钮点不到
- 规则面板底部固定「当前策略」速览（长度 / 深度 / 字符集 / 规则数），随配置实时刷新
- 导出区两行：上排「导出动作 + 编码」，下排「拆分方式 + 分档」
- 预估值用「小字标签 + 18px 等宽数字 + 单位」的仪表读数式排布

对比度实测（WCAG AA：正文 4.5:1、UI 元素 3:1）：
正文 13.8:1 / 15.9:1、次要文字 6.2:1 / 6.5:1、占位符 4.9:1 / 4.7:1——全部达标。
